# PageIndex 渐进式披露(Progressive Disclosure)检索设计对比

> 写作日期：2026-08-02
> 状态：**设计评估，暂不实施**。讨论"借鉴 skill 渐进式加载，对结构树做领域→类目→集合→文档→节点的渐进披露"。

## 0. 动机：现状为什么需要"渐进披露"

当前 L1 选档（`pageindex_mutil/super_tree.py:292-313` + `_build_super_tree`）把**所有候选文档的 mini-TOC 拍平**进一个 6000-token 的 prompt，一次让 LLM 选 3-5 篇。两个后果：

1. **Token 预算截断深度**：`_build_super_tree` 每篇只取 top-8 节点，且子节点只取 `[:5]`（`super_tree.py:388-393`），深层/次要节点在 L1 完全不可见——若相关节点在深层，L1 无从选到。
2. **难负样本下精排弱**：8 个同域干扰文档与 1 个相关文档共处一锅，全凭一次 LLM 判断，精确率失分。

同时存在**未被利用的层级信息**：`closet_index._extract_tags`（`closet_index.py:66-96`）入库时已为每篇生成 3-5 个**领域级抽象语义标签**（"容器编排"而非"Kubernetes"），覆盖领域/场景/方法论维度。但检索时标签与正文 token 混在 `match_closet_tags` 中线性打分（`closet_index.py:149-161`），**从未被当作分级漏斗使用**。

渐进披露的核心：**用多次廉价的定向披露 + 小 LLM 调用，代替一次被迫截断的全景快照**——与 skill 的"先披露元数据→命中后才注入全文"同构。

## 1. 层级映射(复用现有载体，不新造 schema)

| 层 | 概念 | PageIndex 现有载体 | 现状 |
|:--|:----|:----|:----|
| Domain 领域 | 最大粒度 | `closet_tags` 领域抽象标签 | 已生成，未作漏斗 |
| Category 类目 | 次级分类 | `closet_tags` 场景/方法论 + `doc_description` | 已生成，未作漏斗 |
| Collection 集合 | 一组文档 | 共享标签的文档子集(标签聚类) | 需推导 |
| Document 文档 | 单文档 | `documents` 表 | 现 L1 直选 |
| Node 节点 | 最小单元 | Super-Tree `nodes` 树 | 现 L2 召回 |

## 2. 三种形态对比

| 维度 | 形态1：标签级漏斗 | 形态2：两段式选择 | 形态3：递归树导航 |
|:----|:----|:----|:----|
| **描述** | L0 后按 `closet_tags` 领域标签把候选聚成若干"集合"，LLM 先选相关集合，再只对命中集合跑现有 L1/L2 | L1 拆两步：先按 top-node 标题+标签选"类目/文档簇"，命中后再展开该簇子树做精细选档 | 完全分层：领域→类目→集合→文档→节点，每层一次定向 LLM，层层下钻，取代现有 L1/L2 |
| **改动面** | 最小；集中在 `prefilter` + `select_documents`，不动 schema | 中；改 `select_documents`，可能动 `_build_super_tree` | 最大；重写检索主干，动 `router.py`/`super_tree.py`/DB 查询 |
| **Token 成本** | 中低；多一个小 LLM 调用(选集合)，L1 仍在子集上跑 | 中；两次 L1 级调用，但比一次大盘点更准确 | 高；每层一次调用×深度，但每层 prompt 极小 |
| **层次深度覆盖** | 部分；集合内仍受 L1 `[:5]` 限制 | 好；二级展开保深层 | 最好；每层完整披露 |
| **精确率收益** | 中；先刷掉无关集合 → L1 难负样本变少 | 中高；两次判断逐级收紧 | 高；但取决于层级质量 |
| **标签/摘要成本** | 复用已有标签，零新建 | 复用已有 | 每层需披露标题+摘要，索引成本略升(摘要已有) |
| **与现有 L1/L2 关系** | L1/L2 保留，前置漏斗 | L1 被拆分，L2 保留 | 全新递归取代 L1/L2 |
| **风险** | 标签质量波动会传导(低置信标签带偏集合) | 两段判断引入更多 LLM 非确定性(已有 run2run 抖动) | 最大；层级退化时(无结构文档无标签)整套递归失效需兜底 |

## 3. 逐形态拆解

### 形态1：标签级漏斗(最小)
- 在 `Prefilter.prefilter()`(super_tree.py:206-260) 结果上，用 `closet_tags` 的领域标签做一次聚类(candidate→若干 tag 集合)。
- 增加一次小 LLM 调用：给查询 + `[{tag, 文档数}]` 模板，LLM 选出 1-3 个相关领域集合。
- 只对命中集合的文档跑现有 `select_documents`(L1) → `_recall_nodes_for_doc`(L2)。
- **收益**：把 8+1 难负样本的 L1 选择，先压缩到"N 个集合里选 1-2 个"，L1 看的是集内更少更相关的文档，精确率↑。
- **不触碰 schema**；`closet_tags`、`documents` 现有即够。

### 形态2：两段式选择(拉长 L1)
- 第一段：给定 doc list + 每篇 `doc_description` + top-node 标题,LLM 选出 `类目/文档簇`(粗选,可能是"金融风控"这类)。
- 第二段：仅对初选簇内的文档,展开完整子树(含 `[:5]` 之外的深层),讲行 `select_documents` 的精细 top-3/5。
- **收益**：两段各跑在其小 prompt 上,token 更省;第二段能访问深层次。
- **代价**：非确定性×2,与既有的 Tech 抖动(0.714-0.831)叠加。

### 形态3：递归树导航(贴合"领域→类目→集合→文档→节点"原话)
- 定义统一 `navigate(scope, query)`：scope 是"标签集 T / 文档集 D / 节点集 N",每层输出 `{items:[{title, meta}], ...}` 模板,LLM 定向选择下一级 scope。
- `领域级`scope=全部文档的领域标签;命中 → `类目级`(该领域下大类) → `集合级`(共享类目的文档) → `文档级`(逐文档) → `节点级`(树内下钻)。
- **取代现有 L1/L2**；`_recall_nodes_for_doc` 的 relevance 排序逻辑可并入最末节点层。
- **关键前提**：文档须有标签/类目;无结构文档(空树、无标签)此递归无操作对象 → 必须保留 `_content_fallback` 兜底。
- **与上一轮"统一长短文档"的衔接**：形态3在"领域/类目"层天然需要语义标签支撑,而标签来自 `closet_index`(依赖节点标题);即 **形态3 的可用性依赖长短文档统一先把树建出来**。故它是"统一策略"之后的进阶优化。

## 4. 建议(分级)

- **形态1** 是本期收益比最高的落地:复用已存在却闲置的标签分层,不造 schema,直接缓解 L1 难负样本精确率,改动最小。
- **形态3** 是完整形态,但依赖 ①长档已有树+标签 ②短档统一(上一轮方向)。**应先做统一策略,再评估形态3**,避免在无标签文档上自建空转递归。
- **形态2** 是形态1与3之间的折中,可在形态1验证后再决定是否二级展开。

## 5. 与既有四维的耦合

| 维度 | 关系 |
|:----|:----|
| **精确率** | 直接：渐进披露把 L1 的一锅端拆成逐级收紧，难负样本精确率提升是本方案主目标 |
| **延迟** | 多 N 个小 LLM 调用(每层一次)但每层 prompt 极小；相比现状"大盘点+缓存",顺序调用可能净增延迟 → 需与 L1 现状实测对比 |
| **鲁棒性** | 形态3 需保留 `_content_fallback`；短档无标签时基于形态1/2 的漏斗也需兜底 |
| **稳定性** | 多级判断叠加非确定性(run2run) → 形态 2/3 需降温度/种子，且复用 Q1 的投票思路 |
