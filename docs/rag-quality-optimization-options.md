# PageIndex-UV RAG 质量优化方案评估

> 写作日期：2026-08-02
> 状态：**评估文档，暂不实施**。用于对齐第一刀落点，后再进入设计/实现。

## 背景与依据

基于 [pageindex-paper](/home/mimo-workspace/pageindex-paper) 的最新诚实化重设基准（见 `paper/main.tex` 第 5-6 章与 `results/tables/*longdoc_results.md`）：

- 在长结构化文档基准上，PageIndex-UV 平均 F1 = 0.853（第一），最强基线 Self-RAG = 0.833；词法基线≈0.333。
- **所有方法召回均≈1.0**，F1 差距来自**精确率**——在"1 正样本 + 8 个同域难负样本"下能否把相关文档从干扰项中筛出。
- Self-RAG 依赖 **LLM 自反思相关性过滤**，在 Tech(0.889 vs 0.714) 与 Finance(0.944 vs 0.806) 反超我们——它的精确率更高。

## 质量问题的代码定位

对照 PageIndex-UV 真实实现，精确率短板集中在三处：

1. **L1 选文档是"裸 LLM 列表"**（`pageindex_mutil/super_tree.py:274-335`）
   `select_documents` 让模型直接返回 3-5 个 doc_id，顺序即模型自带排序，无二次打分、无精排。难负样本一多容易漏判。

2. **L2 节点召回排序是结构计数**（`pageindex_mutil/agentic/router.py:194-204`）
   相关性分数 = `命中节点数 / 节点总数`，属词面/结构计数而非语义相关性，节点级精确率弱。

3. **全程无 reranker**。评测中 Re-Ranker 基线因离线环境调不动 cross-encoder 而退化为 BM25（README 明确：`search_backend` 默认 `keyword` 不加载模型，无 HF 网络访问）。

4. **CRAG 是事后验证**（`pageindex_mutil/agentic/verifier.py:61-112`）
   在答案生成后才评分，只能 refuse/expand，不提升检索本身精确率，且增加延迟。

## 关键环境约束（决定方案可行性）

- **离线、无 HF 网络** → 神经 reranker（cross-encoder / ColBERT）在此环境跑不通。
- 因此可行的质量杠杆是 **LLM 打分式精排**（与 Self-RAG 同源，但可做得更省）：用更便宜的 `retrieve_model` 对候选打相关性分。

## 候选方案对比

| 方案 | 改动点 | 预期收益 | 成本/风险 | 与配置对齐 |
|:-----|:------|:--------|:---------|:----------|
| **Q1** 推荐 | L1 改"粗选 N(如 12) → 批量 LLM 打分 → top-3/5"，打分+理由显式化 | 击中难负样本精确率，顺带缓解非确定性 | 改动集中在 `select_documents` 一个函数，最小 | `retrieve_model`、`max_candidate_docs`、新增 `rank_k` |
| **Q2** | L2 节点层 LLM 相关性门控（排序→过滤） | 提升节点级精确率 | 每次查询多一次 LLM 调用，延迟↑ | `max_top_nodes_per_doc`、新增阈值 `tau_node` |
| **Q3** | CRAG 前置：检索置信评分从答后搬到答前 | 兼顾精确率与拒答机制 | 改动链路较长（涉及搜索→生成编排） | 复用 `tau_high / tau_low` |

## 质量-稳定性协同

L1 非确定性（评测 Tech F1 0.714–0.831 抖动）与 Q1 天然可合并：打分式精排若采用"候选复制 + 打分/投票"，可在同一批调用内抑制抖动，代价极低。

## 四维全景（供后续规划参考）

| 维度 | 现状 | 杠杆 | 独立度 |
|:----|:-----|:-----|:------|
| **质量** | 精确率短板，等同 Self-RAG 差在无相关性精排 | 方案 Q1/Q2/Q3 | 高 |
| **延迟** | 525-583s/查询，几乎全在 LLM 索引 + L1 + CRAG | 索引降小模型/缓存 section-tree、统一 `retrieve_model`、L2 并行(已 gather) | 中（改 pipeline） |
| **鲁棒性** | 短无结构文本按设计退化到 BM25 级 | 结构感知路由：无结构→扁平 关键词+精排 路径 | 中 |
| **稳定性** | Tech F1 抖动源于 L1/索引非确定性 | L1 降温度/种子、多候选抽样投票 | 高（并入 Q1） |

## 建议落地顺序（草案）

1. **Q1**（质量，改动最小、正中失利点、兼稳定）→ 2. **Q3**（把 CRAG 前置）→ 3. 延迟（索引缓存/降小模型）→ 4. 结构感知路由（鲁棒性）。
